# 帮助文档维护说明

`docs/help/` 是帮助面板的正文唯一来源。改这里的 Markdown，执行 `dotnet build` 即生效，不需要改任何 C#。

本文件面向以后维护这些正文的人：字段怎么填、能写哪些语法、图片放哪、构建失败怎么查。渲染细节的完整契约见 `docs/technical-specification.md` 的「帮助内容管线」，本文件不重复标签映射。

## 1. 目录与页面清单

分区目录固定为 7 个，目录名 = 页面 `id` 前缀。导航顺序由代码里的分区顺序常量固定，不按目录名排序：

| 分区       | 目录         | 页数 | 页面（`id` / 标题 / `order`）                                                                                                                                                                                            |
| ---------- | ------------ | ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 开始       | `start/`     | 4    | `start/index` 帮助中心 1 · `start/getting-started` 快速开始 2 · `start/concepts` 术语与活动流程 3 · `start/data-and-backup` 数据存放与备份 4                                                                             |
| 整合       | `merge/`     | 5    | `merge/overview` 整合板块概览 1 · `merge/import-package` 导入创作者包 2 · `merge/template` 模板与注入点 3 · `merge/correspondence` 对应表与排序 4 · `merge/export` 导出合并工程 5                                        |

本文件 `README.md` 位于 `docs/help/` 根层，不是帮助页，不参与内容生成，也不会出现在导航里。

## 2. 改完就生效的原因

帮助正文不随程序分发为文件，而是在构建期变成程序集里的字符串常量：

1. `dotnet build` 触发 `.csproj` 里的 MSBuild 目标，先构建生成器工程 `tools/HelpContentGenerator/`；
2. 生成器读取 `docs/help/**/*.md`，解析 front matter、校验、把 Markdown 转成 BBCode，并顺带产出检索用纯文本与每页源文件哈希；
3. 产物写到 `src/core/help/Generated/HelpContent.Generated.cs`，参与本次编译。

产物不提交版本库（`.gitignore` 精确忽略，目录内有 `.gdignore` 让 Godot 不扫描）。由此带来两个日常影响：

- 刚 clone 或刚 `git clean` 后，未构建前 IDE 会报找不到 `HelpContent` 类型，先 `dotnet build` 即可；
- 不要手工编辑 `src/core/help/Generated/HelpContent.Generated.cs`，下次构建会覆盖；
- 改 `project.godot` 的 `gui/theme/default_theme_scale` 后也要重新构建：标题字号是构建期按该缩放换算出来的整数像素，不重新生成会保留旧字号。

运行时只读常量，没有 markdown 解析、没有文件 IO，导出时也不需要额外配置。

## 3. front matter 六字段

每个页面的第一段必须是 YAML front matter，以单独一行 `---` 开始、以单独一行 `---` 结束，六个字段缺一不可：

| 字段      | 含义                               | 取值与约束                                                                                  |
| --------- | ---------------------------------- | ------------------------------------------------------------------------------------------- |
| `id`      | 页面唯一键，也是站内链接的解析目标 | **必须等于相对 `docs/help/` 的路径去掉 `.md`**，形如 `merge/export`。前缀必须与所在目录一致 |
| `title`   | 导航项与顶栏显示的标题             | 非空；与正文的 H1 文字保持一致（约定，H1 本身不渲染）                                       |
| `section` | 所属分区                           | 只能是：`开始`、`整合`、`猜测`、`信息`、`录制`、`设置`、`运行与排障`                        |
| `order`   | 分区内排序号                       | 分区内从 1 开始**连续**编号，不留空号、不重复；页数与最后一个 `order` 相等                  |
| `summary` | 一句话摘要                         | 非空，用于搜索结果片段与简介                                                                |
| `tags`    | 检索加权用关键词                   | 行内数组，逗号分隔：`[词1, 词2]`；数量不作硬校验，建议 2~5 个                               |

约定：

- 不支持 front matter 里的注释、多行块、嵌套结构或未列出的字段；
- 字段名区分大小写，写成 `Order`、`ID` 会按缺字段处理；
- 新增页面时同时检查 `order`：插在中间就重排同分区后续页，保持 1..n 连续。

## 4. 允许的 Markdown 子集

只支持下表这些写法。表里没有的写法不受支持；其中 HTML、`####` 及更深标题、嵌套列表、页内锚点、未闭合代码块，以及正文里出现控制字符 `U+0001`（运行期颜色占位符的定界符）都会直接构建失败，其余写法不要使用。

| 写法                           | 渲染结果               | 备注                                                                        |
| ------------------------------ | ---------------------- | --------------------------------------------------------------------------- |
| `## 二级标题` / `### 三级标题` | 放大加粗的标题         | 字号 = 实际正文字号 × 1.4 / 1.15，恒大于正文；页面内一般 3~6 个 H2，H3 少用 |
| 段落                           | 文本段落               | 连续空行归一                                                                |
| `**粗体**` / `*斜体*`          | 加粗 / 斜体            | 可以同时用，交叉嵌套由生成器按顺序闭合                                      |
| 行内代码（一对反引号包住）     | 等宽字                 | 代码里的 `[` 同样会被转义                                                   |
| 围栏代码块（三个反引号）       | 带底色的等宽块         | 可以写语言标记，但不做语法高亮，只原样显示                                  |
| `- ` / `1. ` 列表              | 无序 / 有序列表        | 一项一行                                                                    |
| 表格                           | 表格                   | `\| --- \|` 分隔行必需；不支持合并单元格                                    |
| 提示块：`> **注意**：…`        | 带底色的提示段         | 标签固定四种：`提示`、`注意`、`警告`、`技巧`，各有固定配色                  |
| `[文字](相对路径.md)`          | 可点击，跳到站内页     | 见 §6                                                                       |
| `[文字](https://…)`            | 可点击，交给系统浏览器 | 只允许 http/https                                                           |
| `![说明](images/….png)`        | 图片                   | 见 §5                                                                       |
| `---` 单独一行                 | 分隔线                 | 不要与 front matter 的 `---` 混用位置                                       |

**禁止**（出现即构建失败，并指出文件与行号）：

- HTML 标签，包括 `<br>`、`<div>`、`<img>`；
- `####` 及更深的标题；
- 嵌套列表（缩进的子项）；
- 页内锚点链接（`[…](#小节名)`）；
- 未闭合的围栏代码块。

脚注（`[^1]`）与任务列表（`- [ ]`）不在支持范围内：生成器不会识别，会按字面文本显示，正文不要使用。

写作时另外两条：

- 正文里的 `[` 会被自动转义成 `[lb]`，作者不需要处理；
- 正文开头保留 `# 页面标题` 这一行用于对照，它不会渲染（顶栏已经显示 `title`）。

## 5. 图片

- 图片文件放在 `src/assets/help/images/`；
- Markdown 里写相对路径：`images/<page-id>-<序号>.png`，其中 `page-id` 是把 `id` 里的 `/` 换成 `-`，序号从 1 开始，例如 `info/tables` 的第二张图写作 `images/info-tables-2.png`；
- 生成期检查文件是否存在：**不存在时该行整行不显示**，不渲染占位文字、不报错、不告警，构建日志里会汇总一行「N 张图片缺失」；
- 因此截图可以后补，正文不必等图：补图时只放文件，不用改 Markdown。

图片使用建议：前后留空行，并在正文里用一句话说明该图展示什么。

## 6. 站内链接

- 只用相对路径，指向同仓库内的另一页 `.md`：同分区写 `getting-started.md`，跨分区写 `../run/faq.md`；
- 生成期把它改写成 `help://<id>`，运行时由面板打开目标页；
- **目标文件不存在即构建失败**，避免发布后出现死链；改名或删页时，先全仓搜索旧文件名；
- 不使用绝对路径、不使用 `.md` 之外的站内目标、不写页内锚点。

## 7. 构建与排错

| 命令                          | 用途                                                                                   |
| ----------------------------- | -------------------------------------------------------------------------------------- |
| `dotnet build`                | 常规流程；自动重建生成器并按需重生成 `HelpContent.Generated.cs`                        |
| `dotnet build` 后跑运行时测试 | 一致性测试会比对 28 页的 `id`、`order`、每页哈希与渲染结果；改了 md 却没重新构建必失败 |

生成器也可单独执行：`--input docs/help --output src/core/help/Generated/HelpContent.Generated.cs` 生成，`--verify` 只比对不写。排错时用 `--verify` 能确认「构建产物是否落后于 md」，避免误判为面板问题。

## 8. 新增或修改一页的流程

1. 确认这一页在信息架构里属于哪个分区、排序第几；
2. 在对应分区目录新建 `<页面>.md`，写好六字段 front matter，`id` 与路径一致；
3. 写正文，只用 §4 允许的语法；站内链接只指向确实存在的页；
4. 同分区后续页的 `order` 顺次加一，保持连续；
5. `dotnet build`，确认 0 warning 0 error；
6. 跑运行时测试，确认一致性测试通过。

## 9. 常见报错对照

构建失败时生成器会打印「文件:行 + 原因」并以非零码退出，不写产物。按现象对照：

| 现象                    | 原因                                                             | 处理                                                        |
| ----------------------- | ---------------------------------------------------------------- | ----------------------------------------------------------- |
| 报缺字段                | front matter 六字段少了某一个，或字段名大小写写错                | 补齐字段，按 §3 的准确拼写                                  |
| 报 `id` 与路径不符      | `id` 与「相对路径去 `.md`」不一致，或前缀目录写错                | 让 `id` 等于实际相对路径                                    |
| 报分区非法              | `section` 不在七个取值里                                         | 改成 `开始`/`整合`/`猜测`/`信息`/`录制`/`设置`/`运行与排障` |
| 报 `order` 断号或重复   | 分区内不是 1..n 连续，或两页用了同一号                           | 重排该分区 `order`                                          |
| 报链接目标不存在        | 站内链接指向的文件已被改名/删除，或相对路径层级写错              | 修正路径，或补上目标页                                      |
| 报非法语法              | 用了 HTML、`####` 及更深标题、嵌套列表、页内锚点，或代码块未闭合 | 按 §4 改写                                                  |
| 脚注/任务列表按原样显示 | 这两种写法不在支持范围，被当作普通文本                           | 删掉，或改成普通段落/列表                                   |
| 构建成功但图片位置空白  | 对应图片文件不存在，该行被跳过                                   | 把图片放到 `src/assets/help/images/` 并按 §5 命名           |
| 界面还是旧文案          | 只改了 md，没有重新构建                                          | 重新 `dotnet build`；必要时用 `--verify` 确认               |

## 10. 内容口径

- 正文按**当前版本的实际行为**写，不按需求文档的设想写；界面与文字不一致时以界面为准，并回头修正正文；
- 只写已经实现的功能，不写计划中的功能；
- 内容随版本变化时，与代码改动放在同一个提交里，避免正文与实现漂移。
