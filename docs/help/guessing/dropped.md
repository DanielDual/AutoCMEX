# 丢包与重试

当筛选方式包含 AI 且 AI 请求最终失败时，消息不会得到回复，程序将其保存为丢包记录，供后续重试。记录仅在实际送出回复后移除。

## 产生条件

仅当筛选方式包含 AI 且 AI 请求最终失败（网络失败、超时、重试后仍报错）时产生丢包记录。产生时群聊不会收到回复；若由手动点击「处理」触发，回应显示栏以红字给出失败原因。

群聊消息产生的记录包含来源消息，重试成功可引用原消息回复；手动产生的记录没有来源，重试仅计算判定结果。未配置 AI 模型或 AI 判定为非猜测文本时，不产生记录，也不回复。

## 列表与操作

丢包列表位于右栏底部，每行显示为「[编号] 原文」，界面如下图所示。记录另存来源消息、发送者、失败原因与产生时的筛选方式，供重试使用。列表为空时，三个按钮均为禁用状态。

![丢包列表与三个按钮](images/guessing-dropped-1.png)

「重试全部丢包」重放列表中的全部记录，逐条结果写入回应显示栏；执行期间按钮禁用，文案变为「重试中...」。「清空丢包」清空全部记录，无二次确认。「删除选中丢包」仅删除选中的记录；未选中时给出提示，不修改数据。

## 重试规则

- 重放使用记录产生时的筛选方式，不读取当前设置。
- 下标按「猜测」页当前选中的 Boss 解析；切换 Boss 后重试可能不匹配。
- 重放不新增记录，失败时不删除原记录。
- 链路未运行、未送达任何对端、推送报错或重放后仍非有效猜测时，记录保留，编号不变。

## 结局

| 结局             | 含义                                 | 记录 |
| ---------------- | ------------------------------------ | ---- |
| 已回帖           | 已引用原消息回帖                     | 移除 |
| 无源可回         | 本地手输产生的丢包，结果已算出       | 移除 |
| 无需回帖         | 按回应规则无需回帖                   | 移除 |
| 仍非有效猜测     | 重放后仍非有效猜测                   | 保留 |
| 重放失败         | 重放报错或推送报错                   | 保留 |
| 链路未运行未送达 | 链路未运行、无对端，或未发出任何消息 | 保留 |

结局以「[编号] 说明」逐条写入回应显示栏，标题为「丢包重试结果」。出现「链路未运行未送达」时，应先检查 WebSocket 连接。

> **注意**：Koishi 插件仅保留约 5 分钟内的原消息会话。超过该时间后重试，即使结局显示已回帖，群聊也可能收不到对应回复。

## 记录保留范围

丢包列表仅保存在本次运行期间，退出程序后清空。

## 排查

重试后群聊未收到回复时，检查结局是否为「链路未运行未送达」；若是，检查 WebSocket 面板与 Koishi。重放持续失败时，检查 AI 模型配置、请求地址与请求超时。放弃记录时使用「删除选中丢包」或「清空丢包」。连接问题可查看 [日志](../run/logging.md)。
