# 模糊化处理

模糊化处理把非严格格式的猜测文本交由 AI 转换为严格格式，再进入正常判定。转换内容包括补全省略的编号、调整顺序，以及按别名表把称呼替换为主名。

## 前提

设置中需已选中可用的 AI 模型，见 [AI 模型](../settings/ai-models.md)。未配置时按钮为禁用状态，悬停提示「请先在设置中选择一个有效的 AI 模型」。未配置模型不影响严格格式的手动判定。

## 操作

「模糊化处理」按钮及其转换结果如下图所示。

![模糊化处理按钮与结果](images/guessing-fuzzy-1.png)

1. 在输入框中输入待转换的文本。
2. 点击「模糊化处理」。按钮文案变为「模糊化中...」并禁用，回应显示栏显示「正在调用 AI...」。
3. 转换成功后，输入框内容替换为严格格式文本，回应显示栏显示「完成」与结果。
4. 核对结果后点击「处理」执行判定。

该操作只修改输入框内容，不执行判定，不发送回复，也不产生丢包记录。

转换结果包含以下情况：补全省略的编号，例如 `6 16 26 Alice` 转换为 `6Alice 16Alice 26Alice`；调整顺序，例如 `Alice 12 Bob 23` 转换为 `12Alice 23Bob`；按别名表将称呼替换为主名，表中不存在的称呼由模型推断。对不属于猜测的输入，AI 返回固定标记 `NOT_A_GUESS`。

## 结果

| 结果     | 回应显示栏                        | 输入框         |
| -------- | --------------------------------- | -------------- |
| 成功     | 绿字「完成」及转换结果            | 替换为严格格式 |
| 不像猜测 | 黄字「AI 判定该输入不像猜测文本」 | 不变           |
| 请求失败 | 红字「失败: ...」                 | 不变           |

请求失败时程序自动重试，最多尝试 3 次。每次请求受设置中「请求超时（秒）」约束，默认 100 秒，可调范围 1~600。失败时输入框保留原文，不写入未完成的转换结果。

## 别名表的影响

别名表为空时，称呼完全由模型推断。简称、错称较多时可能转换错误。可在活动前将主要创作者的常用称呼补充到 [对应表与别名表](tables.md) 的别名部分。

## 与群聊托管的关系

该按钮只处理输入框中的文本。群聊消息是否调用 AI，由设置中的「消息筛选」决定，见 [群聊托管猜测](auto-host.md)。当筛选方式为「仅 AI 智能匹配」时，点击「处理」同样会调用 AI，即使输入内容已符合严格格式。
