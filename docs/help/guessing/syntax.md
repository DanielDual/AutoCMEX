# 猜测文本与回应规则

猜测文本由若干「符卡下标 + 创作者」组成，各组之间以空格分隔。程序按当前 Boss 的符卡序号解析下标，并按固定规则回复处理结果。

## 格式

格式为 `<符卡下标><创作者>`，多组之间使用单个空格分隔，例如 `1Alice 2Bob 3Charlie`。

- 下标为当前 Boss 内的符卡序号，从 1 开始，与对应表的行序一致。
- 创作者可写主名或别名。写别名时先按 [对应表与别名表](tables.md) 转换为主名再比较，比较不区分大小写。
- 数字与名字之间、名字内部均不能包含空格。
- 一条消息视为一条猜测文本；使用换行分隔会被判为无法解析。
- 同一张符卡重复填写相同的创作者，只计一次。

示例：`1Alice 2Bob` 有效；`1 Alice 2 Bob` 因数字与名字断开而无效；分成两行发送同样无效。

## 处理与显示

点击「处理」后，回应显示栏先给出将发送到群里的语句，再逐条列出每张符卡的判定结果：猜对、猜错（附实际创作者）、因已猜出而跳过、因创作者未填写而无法判定。群里只收到第一句，逐条明细仅在本页显示。

![回应显示栏的判定明细](images/guessing-syntax-1.png)

「模糊化处理」不参与判定，其作用是把输入框中的文本转换为上述格式；转换完成后仍需点击「处理」，见 [模糊化处理](fuzzy.md)。

## 回应规则

程序先统计本次猜测中尚未猜出的符卡数量，再按数量回复：

| 本次有效符卡数   | 回应                          | 说明             |
| ---------------- | ----------------------------- | ---------------- |
| 3 张及以上       | 「猜对张数/总张数」，如 `2/3` | 部分猜对也给比例 |
| 2 张             | 全对回 ✔️，有错回 ❌️         | 不给比例         |
| 1 张或 0 张      | 「必须猜两个以上」            | 只猜一张不成立   |
| 0 张且全部已猜出 | 「所有猜测的符卡均已被猜出」  | 优先于上一行     |

若本次猜测涉及已猜出的符卡，回应末尾注明「（N 已被猜出，已跳过）」。

## 自动标记

本次有效符卡为两张以上且全部猜对时，程序将涉及的符卡标记为「已猜出」。此后这些符卡不参与判定，信息板块的两张统计表随之更新，见 [两张统计表](../info/tables.md)。

猜错、仅猜一张，或其中包含创作者未填写的符卡时，不会标记。

## 错误处理

严格格式下，回应显示栏以红字说明原因：格式不符、下标越界或某一段无法解析。群里不回复，也不产生丢包记录。

一条猜测内只要有一段无法解析，整条都不处理，不会只判定前半段。因此格式错误需要整条重发。

筛选方式包含 AI 时，格式不符的文本会先交给 AI 尝试转换再判定；转换失败才产生丢包记录，见 [群聊托管猜测](auto-host.md)。

## Boss 与下标

下标始终按「猜测」页当前选中的 Boss 解析，群聊消息同样如此。切换 Boss 后，下标从新 Boss 的 1 重新开始；写 0 或超过当前符卡数会被判为越界。

> **注意**：切换 Boss 后，群内成员可能仍按上一 Boss 的编号发送猜测，建议在切换时于群内说明。
