# 对应表与别名表

猜测板块左侧为两张表：符卡—创作者对应表记录每张符卡的创作者，创作者别名表将群内使用的称呼转换为创作者主名。判定同时使用这两张表。

## 符卡—创作者对应表

该表分为符卡名、创作者、已猜出三列。Boss 占一行，其下为该 Boss 的符卡；符卡下标为行序，从 1 开始。

![对应表三列与「已猜出」勾选](images/guessing-tables-1.png)

创作者为空时，行内显示 `(未揭晓)`。此类符卡无法判定对错，回应中提示待揭晓。若某张符卡显示「待揭晓」，表示该列未填写；导入时该列为空即会出现此状态。

Boss 名与符卡名均可就地修改；Boss 名修改后同步到下拉框。第三列为勾选框，表示「已猜出」；判定为全对时程序自动标记。该列仅表示状态，不改变创作者。

表下方按钮为「添加 Boss」「添加符卡」「删除」。「删除」删除选中行；选中 Boss 行时，该 Boss 及其全部符卡一并删除。修改自动保存，无单独的保存操作。

## 导入与导出

| 方向 | 文件              | 要求                                                         |
| ---- | ----------------- | ------------------------------------------------------------ |
| 导入 | `.csv` 或 `.xlsx` | 三列：Boss、符卡名、创作者；首行为表头，列名不限但列序须一致 |
| 导出 | `.csv`            | 表头固定为 `Boss,符卡名,创作者`，包含全部 Boss 的每张符卡    |

导入要求至少三列，缺少时提示「列缺失」。文件需为 UTF-8 编码，否则中文显示为乱码。导出固定为 CSV，内容为全部 Boss 的符卡，不限于当前 Boss。

导入为整体替换，不追加到现有数据。若在活动过程中导入旧表，当前表与「已猜出」标记会被清除。对应表由整合板块「导出对应表」生成，见 [导出合并工程](../merge/export.md)。

> **警告**：导入会清除当前对应表与「已猜出」标记。未导出的表应先执行「导出」。

## 创作者别名表

该表只有一列「创作者 / 别名」。父行为主名，显示与判定均使用主名；子行为别名，仅在处理猜测文本时用于转换。没有别名的创作者只有父行。

![创作者别名表](images/guessing-tables-2.png)

按钮为「导入别名表」「添加」「删除」「添加别名」「导出别名表」。「添加」新增创作者；「添加别名」为选中的创作者添加一条别名，选中其别名子行同样有效；未选中任何行时提示并中止。「删除」按选中行处理：主名行删除整个创作者，别名子行仅删除该条别名。就地修改只影响当前行。

别名表格式为第一列主名，之后每列一条别名，例如 `主名,别名1,别名2,...`；至少两列，首行为表头。导出时按最长行补齐空列。

## 别名转换

判定前，程序按别名表将猜测中的称呼转换为主名，规则有两条：

- 称呼本身是某行主名时不替换，即主名优先。
- 同一别名被多行声明时，以表中先出现者为准。

主名用于显示与判定，别名用于登记简称、错称与拼音。别名表为空时仍可判定，但称呼由模型推断，转换准确度下降。

## 常见问题

导入提示「列缺失」：缺少表头行或列数不足，对应表至少三列，别名表至少两列。导入后内容为空：检查文件编码是否为 UTF-8。创作者列为空：表示答案未填写，判定不给出对错。判定流程见 [猜测文本与回应规则](syntax.md)，整体流程见 [猜测板块概览](overview.md)。
