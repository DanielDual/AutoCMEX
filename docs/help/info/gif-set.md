# 符卡 GIF 集

符卡 GIF 集位于信息板块第一栏。每个集由一个文件夹构成，包含清单 `manifest.json` 与若干 GIF 文件；发布时以合并转发生成一条可展开的卡片。

## 集的结构

集根目录包含清单与各 GIF 文件，例如 `1.gif`、`2.gif`。清单逐条记录序号、符卡名、文件名与像素尺寸；界面显示与发布内容均以清单为准，不依据目录中的文件名推断。

图名不受限制，但须与清单中的 `fileName` 一致。清单与目录不一致时，导入失败。

清单键名为 camelCase，读取时不区分大小写，并允许注释与尾随逗号。

| 字段          | 含义                                                                     |
| ------------- | ------------------------------------------------------------------------ |
| `setName`     | 集名；为空时使用文件夹名                                                 |
| `bossLabel`   | 来源说明，仅用于展示                                                     |
| `generatedAt` | 生成时间，仅用于展示                                                     |
| `entries`     | 条目数组，每条含 `index`、`spellCardName`、`fileName`、`width`、`height` |

最小清单示例：

```json
{
  "setName": "示例集",
  "bossLabel": "SampleBoss",
  "generatedAt": "2026-09-25 12:00:00",
  "entries": [
    {
      "index": 1,
      "spellCardName": "非符",
      "fileName": "1.gif",
      "width": 640,
      "height": 480
    }
  ]
}
```

集有三个来源：整理为文件夹后点击「导入文件夹」；打包为 `.zip` 后点击「导入压缩包」；或在信息板块点击「录制」运行一轮，产物自动导入并设为当前集。录制产物与手工整理的集结构相同，导入流程一致，见 [符卡 GIF 录制](../recording/overview.md)；录制参数在 [录制设置](../recording/settings.md) 中配置。

## 导入校验

导入时逐项检查清单与目录：清单存在且可解析；条目非空；序号为正整数且不重复；符卡名非空；`fileName` 为集根目录下的纯 `.gif` 文件名，且在清单内不重复；清单声明的文件均存在；集目录中不存在未在清单声明的 `.gif`。

任一条件不满足时，导入整体拒绝。弹窗逐条列出原因，该集不写入本地数据，已有集不受影响。

导入失败时，弹窗列出的条目即为需要修正的位置。常见原因为目录中存在未写入清单的图片，或清单中的文件名与实际文件不一致。校验仅在导入时执行，导入后对外部修改的文件不会重新检查；发布前会再次检查文件是否存在且非空。

> **注意**：文件夹导入采用就地引用，不复制文件。导入后移动、重命名或删除原目录，栏内卡片与发布均无法找到图片。

## 显示与切换

栏顶下拉框用于切换当前集。切换后，卡片列表与发布内容同时更新。

每张卡片显示「序号. 符卡名」与对应动图。为避免大集占用过多内存，仅对视口内的少量卡片解码，滚动时加载其余卡片。

![GIF 集下拉与卡片列表](images/info-gif-set-1.png)

## 与猜测板块的关系

集内的符卡名与序号仅来自清单，不与猜测表做序号对齐，也不随当前 Boss 变化。集对应一次整合或录制的产物，与当前 Boss 未必同源，序号不一致属于正常情况。

## 发布

点击「发布 GIF 集」后，当前集以合并转发发送。发送前检查各图片是否存在且非空；存在缺失或空文件时，列出对应条目并停止发送。
