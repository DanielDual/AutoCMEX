# 信息板块概览

信息板块用于向活动群发布猜测阶段需要的公开内容，包括符卡 GIF 集、符卡猜测情况表、创作者剩余未被猜测符卡数表与活动规则。四栏位于同一页面，可分别发布。

## 四栏内容

四栏从左到右排列；窗口宽度不足时出现横向滚动。

| 栏                         | 内容                                                                                 |
| -------------------------- | ------------------------------------------------------------------------------------ |
| 符卡 GIF 集                | 导入或录制得到的集（见 [符卡 GIF 集](gif-set.md)），一张符卡对应一个动图，按序号排列 |
| 符卡猜测情况表             | 当前 Boss 的全部符卡，含符卡编号、符卡名与猜出状态；已猜出的行整行染绿               |
| 创作者剩余未被猜测符卡数表 | 按创作者统计剩余未被猜测的符卡数                                                     |
| 活动规则                   | 纯文本，发布时按原文发送（见 [活动规则与发布](publish.md)）                          |

![信息板块四栏总览](images/info-overview-1.png)

每栏下方有独立的发布按钮，各栏互不影响。重新发布某一栏时，其他栏的内容不变。

四栏没有固定的填写顺序。符卡 GIF 集与活动规则通常在活动开始前准备；统计表通常在猜测开始后发布，在此之前，所有符卡的创作者栏为空。

## 下栏与目标群

页面下半部分为目标群列表与发布入口。目标群列表与设置页「信息」类别中的列表为同一份数据，下栏的勾选状态即设置项「启用」，任一处修改后另一处同步。

「刷新群列表」向 Koishi 查询群列表并并入本地配置。新并入的群默认不勾选；Koishi 未连接时提示刷新失败。群列表的维护见 [信息类别与目标群](../settings/info.md)。

「一键转发」按固定顺序依次发布四栏内容。「猜测表变化自动推送」用于在符卡猜测情况表内容变化时自动发布该表，适用于持续托管猜测的场景。两种方式的规则见 [活动规则与发布](publish.md)。

发布需要可用的 Koishi 连接。连接不可用时，各栏发布与一键转发均返回失败结果，不会静默丢弃。

## 群内呈现方式

符卡猜测情况表与创作者剩余表以图片消息直接发送；符卡 GIF 集与活动规则以合并转发发送。两类内容在群内的展开方式不同，属于预期行为。

## 操作顺序

1. 准备符卡 GIF 集：导入文件夹或压缩包，或在信息板块使用「录制」生成（见 [符卡 GIF 录制](../recording/overview.md)）。
2. 确认目标群：若设置中已有目标群，直接在下栏勾选；否则使用「刷新群列表」获取。
3. 发布单栏内容，或在勾选目标群后使用「一键转发」。

## 与猜测板块的关系

两张统计表的数据来自猜测板块的当前 Boss。切换 Boss 后，两张表随之切换；标记「已猜出」、修改符卡名或创作者后，表自动刷新，无需重新打开页面。
