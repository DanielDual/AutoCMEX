# 对应表与排序

对应表记录每张符卡对应的创作者。其行序同时是注入顺序与导出 CSV 的行序，并影响猜测板块中的符卡编号。

## 表的来源

每导入一个创作者包，该包的符卡按包内顺序追加到表尾，顺序与导入顺序一致。

创作者列取自包名推导出的名称，导入后在整合板块无法修改；需要修改时应重命名 zip 后重新导入，见 [导入创作者包](import-package.md)。

非符与符卡一样占用一行。表的行数由导入的包数量与各包的符卡数决定。

## 调整顺序

![对应表与按模式重排](images/merge-correspondence-1.png)

上图为对应表面板，下方为「上移」「下移」「按模式重排」按钮与模式下拉框。

1. 在列表中选中一行。
2. 点击「上移」或「下移」，每次移动一行。

未选中任何行时，这两个按钮不产生变化。行数较多时，逐行移动效率较低，可以使用「按模式重排」。

按钮下方的下拉框用于选择模式。选中模式后点击「按模式重排」，整表按该模式重排：

| 模式              | 方式                                             | 适用情况                     |
| ----------------- | ------------------------------------------------ | ---------------------------- |
| 随机              | 整表打乱                                         | 不希望从顺序推断创作者       |
| 交替（非符/符卡） | 按两类数量将非符与符卡交替排列，两类内容各自随机 | 需要非符与符卡交替出现       |
| 按创作者分组      | 同一创作者的符卡聚集，组序按首次出现，组内随机   | 需要同一创作者的内容连续出现 |

> **注意**：重排没有撤销。每次点击都会重新随机，连续点击两次结果不同。表中只有一类内容时，「交替」与「随机」的结果相同。

## 顺序的影响

合并工程中的出场顺序由该表决定。随机与交替会打乱创作者与符卡的排列规律，按创作者分组则使同一创作者的内容连续出现；选择取决于活动设计。

导出的对应表按同一顺序写入行。导入猜测板块后，符卡编号按当前 Boss 的行序计算，调整顺序会改变群内「第几张」所指的符卡。活动开始后应避免大幅调整顺序。

## 状态的归属

对应表随整合工程保存，不是全局配置。重启程序后表仍然存在；切换到其他整合工程时，显示的是该工程的对应表。删除创作者包时，该包在表中的条目同时被移除。

对应表导入猜测板块后，在猜测板块的修改不会回写到整合侧的这份表，两侧数据可能不一致，需要事先确定以哪一侧为准。相关说明见 [对应表与别名表](../guessing/tables.md)。
