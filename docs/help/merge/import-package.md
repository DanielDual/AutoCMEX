# 导入创作者包

每收到一份投稿，需要在整合板块执行一次导入。导入过程解析包内工程，生成包列表条目、对应表条目与三类清单。

## 支持的包

只接受 `.zip`，文件选择框也只列出 `.zip`。解压后，程序在包内所有子目录中查找 `.lstges` 工程文件，不要求位于根目录。包内存在多份 `.lstges` 时只读取其中一份，读取顺序没有保证，因此建议一包一份工程。`.rar`、`.7z` 等格式需要先转换为 zip。

创作者名由 zip 文件名推导：取第一个下划线之后的整段，`01_Alice.zip` 得到的创作者名为 `Alice`。文件名不含下划线时，整个文件名作为创作者名。建议采用「序号\_创作者.zip」的命名方式。

## 导入结果

![导入后的创作者包列表与三类清单](images/merge-import-package-1.png)

上图左侧为已导入的包列表，下方为当前包的符卡、资源与对象清单。

导入成功后，包列表新增一行「创作者名（包名）」，对应表按包内顺序追加该包的符卡。选中包列表中的不同条目时，下方三类清单随之切换。

| 清单     | 内容                         | 用途                           |
| -------- | ---------------------------- | ------------------------------ |
| 符卡清单 | 符卡名，非符标注「（非符）」 | 核对对应表是否缺卡             |
| 资源清单 | 「类型: 相对路径」           | 核对贴图、音频等引用是否已抽出 |
| 对象清单 | 「类型: 名称」               | 核对敌机、道具等定义是否已抽出 |

清单按包显示，切换包后需要重新查看。符卡清单缺少条目时，对应表会同时缺少相应行，导出后该部分不会出现在合并工程中。包内被禁用的符卡不会被抽出，清单与对应表中均不包含。

## 创作者名

创作者名只能由包名推导，整合板块不提供修改入口。名称不正确时，按「序号\_创作者.zip」重命名文件后重新导入，并删除原有包。未删除旧包时，包列表会同时存在两个包，对应表也会追加重复的符卡。

## 删除包

「删除所选包」从当前工程中移除该包及其在对应表中的条目，不修改磁盘上的 zip 文件。删除以选中的行为准，未选中任何行时不会产生影响。已导出的产物不会随之更新，需要重新导出。

## 导入失败

> **注意**：导入失败时程序不会弹出提示，原因记录在日志中（见 [日志](../run/logging.md)），包列表也不会新增条目。导入后应确认包列表是否发生变化。

常见原因有三类：文件不是 zip、包内没有 `.lstges`、`.lstges` 无法解析。前两类可以直接用压缩软件确认；第三类与工程文件本身有关，例如文件损坏或编码异常，需要创作者重新提交。失败的操作不会留下部分数据，修正后可重新导入。
