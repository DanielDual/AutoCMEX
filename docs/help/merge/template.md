# 模板与注入点

合并以模板工程为基础：创作者包的符卡、对象与资源节点插入模板的指定位置，模板其余内容保持不变。

## 模板的要求

模板是合法的 `.lstgproj` 工程，能够用 LuaSTG Editor Sharp 打开并打包。模板单独打包时能够产出的内容，合并后同样应当可以产出；模板本身无法正常打包时，合并产物会存在同样问题。

## 三条路径

| 配置项     | 填写内容                                                           | 用途                               |
| ---------- | ------------------------------------------------------------------ | ---------------------------------- |
| 模板工程   | 模板 `.lstgproj` 的完整路径                                        | 合并产物的基础，所有内容注入该工程 |
| Sharp 目录 | Editor Sharp 的安装目录，其中包含 `LuaSTGEditorSharp.Core.Cli.exe` | 将合并工程编译打包为 mod zip       |
| 插件 dll   | 编译插件 dll 的文件名，例如 `LuaSTGPlusLib.dll`                    | 打包时由 Sharp 使用                |

三个输入框没有「浏览」按钮，需要直接粘贴路径。内容在输入后立即写回，重启程序仍然有效；更换机器或移动目录后需要重新填写。

Sharp 一栏填写安装目录，而不是 `LuaSTGEditorSharp.Core.Cli.exe` 文件本身，程序会在该目录中查找 Cli。插件 dll 一栏填写文件名，打包时原样传给 Cli。未填写这两项时仍可导出工程与对应表，但不会生成 mod zip，右下列表会提示跳过打包。

## 注入点

模板需要用注释标出三处插入位置，注释文字分别为 `Insert spellcards here`、`Insert resources here`、`Insert objects here`，不区分大小写。注释中包含上述短语即视为命中，短语后可以附加其他说明。

合并时各类内容分别注入对应位置：符卡进入符卡注入点，敌机、道具等对象定义进入对象注入点，贴图音频等资源节点进入资源注入点。插入位置由模板决定，因此使用注释标记，程序不进行推断。

## 检测注入点

![模板三条路径与注入点状态行](images/merge-template-1.png)

上图为模板配置区，按钮下方为注入点状态行。

1. 在模板工程输入框中填写路径。
2. 点击「导入并检测注入点」。
3. 查看按钮下方的状态行。

状态行有以下几种内容：

- 「注入点：待导入模板」：尚未检测。
- 「注入点：符卡✓ 资源✓ 对象✗」：✓ 表示已找到，✗ 表示未找到。
- 「请填写模板路径」或「解析失败：…」：路径为空，或文件无法读取。

「解析失败」的原因包括模板格式错误、文件不完整或选择了其他文件。检测只读取模板，不修改文件，重复检测不会产生影响。

## 缺少注入点

缺少符卡注入点时，导出会报告「模板缺少符卡注入点」并中止合并。

缺少对象或资源注入点时，合并不中止，但对应类型的内容不会注入，原因记录在日志中（见 [日志](../run/logging.md)）。补充注释后需要重新检测。

模板文件修改后需要再次点击检测，状态行才会更新。资源注入点只对顶层资源节点有效；合并模式选择「按顶层文件夹整搬」时，资源随文件夹一起搬运，不使用该注入点。
