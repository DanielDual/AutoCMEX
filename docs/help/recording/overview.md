# 符卡 GIF 录制

录制功能驱动 LuaSTG 引擎逐张录制当前 Boss 的符卡与非符，输出与手工整理的 GIF 集结构相同的产物。录制入口位于信息板块（[信息板块概览](../info/overview.md)）的符卡 GIF 集栏。

## 产物

每张战斗卡生成一个 GIF，文件名为 `序号.gif`，与手工整理的集结构相同：同一文件夹内包含 `manifest.json` 与各 GIF。序号按战斗顺序排列，符卡与非符统一计数，从 1 开始；未成功录制的卡保留空号，因此序号可以不连续。

一轮录制结束时写出 `manifest.json`，并自动导入为当前集。一轮录制对应一个 Boss 的卡表；切换 Boss 后需重新运行。

## 操作顺序

1. 在信息板块的符卡 GIF 集栏点击「录制」。
2. 程序执行前置检查：引擎目录、录制插件、沙箱根目录。
3. 检查不通过时弹出「暂时无法录制」并说明原因，不弹出文件选择框；按提示在录制设置中处理。
4. 检查通过后选择工程包 `.zip`，再选择产物输出目录。
5. 录制在进度对话框中执行，结束后自动导入。

前置检查在文件选择之前执行：引擎目录或插件不满足条件时无法产出内容，先给出原因可避免无效选择。

## 进度对话框

标题为「符卡 GIF 录制」，内容随阶段更新：

![录制进度对话框](images/recording-overview-1.png)

- 阶段行显示枚举中、录制中、归集中；取消后显示正在取消。
- 显示总数、已完成与失败计数。
- 显示各 worker 正在录制的卡，格式为「worker 1：3. 卡名」；重录时标出尝试次数。
- 提供「取消录制」按钮；关闭窗口等同于取消。

> **注意**：取消后，已归集的产物与报告保留；正在录制与尚未轮到的卡记为未录制，报告中标记为已取消。

## 结束之后

对话框汇总一行「本轮录制：成功 X　失败 Y　未录制 Z　共 N 张」，随后自动导入为当前集。

无成功产物时跳过导入，仅在对话框中说明。自动导入被拒时，产物、报告与清单保留在输出目录中，可按提示手动导入。输出目录中若存在上一轮遗留的 `.gif`，集内校验会因存在未在清单声明的文件而失败，因此每轮应使用空的输出目录。

失败计数不为 0 时，可在报告与 worker 行中查看对应卡片的原因。已归集的产物即为信息板块 GIF 集栏中的卡片；序号与卡名可用于与报告核对。

## 前置确认

- 录制设置中的引擎目录、两个录制插件与沙箱根目录均显示可用，见 [录制设置](settings.md)。
- 整轮耗时随卡数与并行度变化。
- 长卡在帧数上限处被截断属于正常产物，报告中会标注。
- 单张产物超过 30MB 或首次录制录满被截断时，自动以第二档间隔重录一次，采用第二次的产物。
