# 日志

「日志」页显示运行记录，包含操作结果与错误信息。发布、连接或录制失败时，原因通常记录在此。

## 界面

顶部为「级别:」与「模块:」两个筛选，右侧为「暂停」与「清空」，中部为日志列表，底部显示日志目录与内存缓冲条数。缓冲条数表示界面中保留的记录数量，达到上限后最早的记录被丢弃。

- 级别可选 All、Info、Warn、Error；「All」表示 Info 及以上级别。
- 模块默认为 All，随日志中出现的模块名增加，用于筛选特定模块的记录。
- 「暂停」停止向界面追加记录，按钮变为「继续」；日志文件仍继续写入。
- 「清空」清空界面与内存缓冲，不删除日志文件。

![日志板块界面](images/run-logging-1.png)

图中为顶部筛选、日志列表与底部目录信息。

排查时可先将级别筛选为 Warn 或 Error，再将模块筛选为相关模块（例如发布、群聊、录制），缩小范围后再查看具体记录。

## 文件位置

当前日志文件为 `app.log`，默认位于系统临时目录下的 `AutoCMEX/logs`，不在用户数据目录中。日志放在临时目录，不占用用户数据目录空间。实际路径以页面底部的「日志目录」为准。

> **注意**：内存缓冲默认保留最近 1000 条，超出后丢弃最早的记录，更早的记录只存在于日志文件中。需要较早记录时应查看日志文件。

临时目录可能被系统或清理工具删除，需要保留的日志应及时复制；其余配置与数据的存放位置见 [数据存放与备份](../start/data-and-backup.md)。

## 落盘配置

底部面板可修改两项配置，点击「Apply Config」后写回：

| 配置项         | 范围                | 说明                     |
| -------------- | ------------------- | ------------------------ |
| 最大日志文件数 | 1~1000              | 轮转后保留的文件数量上限 |
| 最低日志级别   | Info / Warn / Error | 仅影响界面内存缓冲       |

轮转仅在点击「Apply Config」时执行一次，程序不会在后台定时轮转。未点击时，日志持续写入当前文件，不会自行切分；输入数值但未点击「Apply Config」不会生效。

最低日志级别只过滤界面内存缓冲，日志文件仍记录全部级别。界面中看不到 INFO 级记录，不代表文件中没有；调低界面级别也不会减少文件写入。

## 提供日志文件

1. 复现问题前点击「清空」，使记录仅包含本次操作。
2. 复现后将日志目录中的文件交给维护者。
3. 发送前检查内容：日志中可能出现群 ID、昵称与猜测原文。

同时提供复现步骤与时间点可缩短定位时间。日志目录中可能存在多个轮转文件，应一并提供。

## 常见现象

**界面无日志显示**：检查是否处于「暂停」状态，以及级别与模块筛选是否过滤了内容。被过滤的记录仍存在于日志文件中。

**日志文件有多个**：轮转会将当前文件按序号重命名，`app.log` 变为 `app.1.log`，依次类推；保留数量由「最大日志文件数」决定。
