# WebSocket 状态面板

「WebSocket」页显示当前连接实例的运行状态，包括模式、端口或地址、连接数与错误信息。排查群聊或发布问题时，以该面板的显示为准。

## 显示来源

面板中的模式、端口或地址、连接数与错误信息均取自正在运行的连接实例，而非设置页中保存的配置。设置修改后，实例重建完成前两者可能不一致；此期间以面板为准。

程序同一时刻只运行一个连接实例，并只维护一条链路。因此启停按钮只需操作一次：重复点击不会建立额外链路，但可能中断正在进行中的重连。

![WebSocket 状态面板（Server 模式）](images/run-websocket-1.png)

图中为 Server 模式：上方依次为模式行、状态行、端口行、连接数行与事件行，下方为客户端列表，最下方为启停按钮。

## 面板各行

| 位置         | 内容                                                                                 |
| ------------ | ------------------------------------------------------------------------------------ |
| 模式行       | 「模式: Server（等待连接）」或「模式: Client（主动连接）」                           |
| 状态行       | Server 为「运行中」或「已停止」；Client 为「已连接」「未连接（重连中）」或「未连接」 |
| 端口或地址行 | Server 显示实际监听端口；Client 显示完整对端地址                                     |
| 连接数行     | 仅 Server 显示；Client 只有一条链路，该行隐藏                                        |
| 事件行       | 最近一次连接或断开的时间                                                             |
| 错误行       | 最近一次启动或运行失败的原因；无错误时隐藏                                           |
| 客户端列表   | Server 标题为「已连接客户端:」；Client 标题为「连接的对端:」；每秒同步一次           |
| 开关按钮     | Server 为「启动」「停止」；Client 为「连接」「断开」                                 |

端口行与地址行对应不同模式：Server 显示自身监听端口，Client 显示所连接的对端地址。核对时应先确认当前模式。

事件行记录最近一次连接或断开的时间。错误行仅显示最近一次失败原因，新的状态会覆盖此前内容，因此失败复现后应立即查看。

客户端列表在 Server 模式下列出已接入的 Koishi 侧连接，在 Client 模式下仅显示一条对端。内容每秒自动同步。

## 状态与按钮

状态行与按钮的着色反映实际运行状态，正常为绿色，异常为红色。状态行表示是否连通，按钮表示点击后的动作。

Client 的「未连接（重连中）」表示实例仍在运行并正在尝试重连，此时按钮为「断开」。更换地址时，应先断开连接，修改设置后再重新连接；对处于重连状态的实例反复点击按钮会干扰重连过程。

Server 的「已停止」表示实例已停止；状态为「运行中」但连接数为 0，表示端口已监听但没有客户端接入。两种情况的原因与处理方式不同。

## 连接排查

**Client 一直未连接**：查看错误行。地址为空时显示「未配置 Koishi 地址」；否则核对 Koishi 是否运行，以及地址与端口是否与 Koishi 侧一致。

**Server 无已连接客户端**：连接数为 0 表示 Koishi 尚未接入。确认 Koishi 侧使用同一端口，且插件已安装并启用。

**端口被占用**：错误行会说明启动失败。在设置页「群聊」类别修改端口，并同步修改 Koishi 侧配置，返回面板确认状态。

修改设置后实例会重建，面板随之更新，无需手动点击「启动」。若重建后状态不变，先查看错误行。面板不保留历史记录，前后变化需查看 [日志](logging.md)。连接参数的配置见 [群聊连接与 Koishi](../settings/chat.md)。
