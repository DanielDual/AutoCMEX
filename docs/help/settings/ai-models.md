# AI 模型

AI 模型用于两种情况：将非标准格式的输入转换为标准猜测文本（模糊化处理），以及判断群聊消息是否为猜测（智能匹配）。模型在设置页的「AI模型」类别中配置，具体使用方式见 [模糊化处理](../guessing/fuzzy.md) 与 [群聊托管猜测](../guessing/auto-host.md)。

## 用途与前提

模糊化处理与智能匹配均需调用模型。按标准格式手动输入的猜测不经过 AI，因此在未配置模型时仍可正常处理。

未配置模型或未选中有效模型时，猜测页的「模糊化处理」按钮为禁用状态，悬停提示为「请先在设置中选择一个有效的 AI 模型」。

## 添加与编辑

每个模型包含四项：「API 格式:」「请求地址:」「模型 ID:」「API 密钥:」。API 格式可选 OpenAI 或 Anthropic：OpenAI 兼容接口选择 OpenAI，Anthropic 官方接口选择 Anthropic。请求地址应填写服务商文档中给出的完整端点地址，而非仅填写域名。模型 ID 是调用时使用的标识，与厂商控制台中的显示名称不同。

1. 点击「添加模型」，列表末尾新增一条记录，格式默认为 OpenAI。
2. 填写上述四项，密钥默认以星号遮挡。
3. 核对密钥时点击输入框右侧的「显示」，完成后点击「隐藏」恢复遮挡。
4. 删除模型时点击该条记录中的「删除」。

可配置多个模型。下拉列表中每项显示为「模型 ID（API 格式）」，未填写模型 ID 时显示「（未命名）」。

## 激活模型

「激活模型:」下拉框决定当前使用的模型。第一项为「（未选择）」，选择该项等同于未配置。缺少地址、模型 ID 或密钥的模型在下拉框中显示为不可选。

模糊化处理与智能匹配共用同一个激活模型，当前版本不支持按功能分别指定模型。

## 测试连接与超时

每条模型记录均有「测试连接」。点击后按钮文字变为「测试中...」，结果为「连接成功」或「连接失败」，两秒后恢复。测试使用与正式请求相同的配置，测试失败时模糊化处理同样无法成功。

测试连接最多等待 30 秒，与「请求超时」设置无关；该上限仅用于连接验证，避免在地址不可达时长时间等待。测试通过仅表示地址、密钥与模型 ID 可用，不保证模糊化输出符合预期。

「请求超时(秒)」范围为 1~600 秒，默认 100 秒，作用于所有 AI 请求，包括模糊化处理与智能匹配。调大该值后，单次请求可能占用更长时间。

AI 调用失败时返回错误，不会自动重试。请求超时需重新发起；若同一模型持续失败，可更换模型后重试。

## 密钥存储

密钥以掩码显示，保存时加密，密钥文件位于用户数据目录，且不会以明文写入日志。整个数据目录应视为凭证：不应发送给他人，备份方式见 [数据存放与备份](../start/data-and-backup.md)。分享错误截图前应确认其中未包含密钥。

## 常见失败原因

「连接失败」：核对密钥、请求地址与模型 ID 是否与服务商控制台一致，并确认 API 格式正确。程序无法区分是哪一项错误。

下拉框中某项不可选：该模型缺少地址、模型 ID 或密钥。补齐后重新进入本页。

「模糊化处理」仍为禁用状态：未选中有效模型。需在顶部下拉框中选择，或先完成测试连接。
