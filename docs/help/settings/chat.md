# 群聊连接与 Koishi

群聊中的猜测要进入程序，需要建立 Koishi 与 AutoCMEX 之间的 WebSocket 连接，并在 Koishi 侧安装本项目的插件。连接参数与插件安装均在本页配置。连接建立之前，手动输入猜测、生成与发布图片仍可正常使用，只是群聊消息需自行复制。

## 连接模式

设置中的「连接模式:」决定 AutoCMEX 在连接中的角色：

| 设置项         | 取值                                                | 说明                            |
| -------------- | --------------------------------------------------- | ------------------------------- |
| WebSocket 端口 | 1~65535，默认 5140                                  | 修改后立即写回，连接随之重建    |
| 连接模式       | Server（等待连接）/ Client（主动连接），默认 Server | AutoCMEX 监听端口或主动连接对端 |

![群聊类别页布局](images/settings-chat-1.png)

Server 模式下 AutoCMEX 在本机监听端口，Koishi 连接该端口；Client 模式下 AutoCMEX 主动连接 Koishi 的 WebSocket 地址。两种模式要求两端使用同一端口或地址。

端口修改会立即写回并重建连接，修改时应同时更新 Koishi 侧配置，仅修改一端不会生效。

## Client 模式地址

选择 Client 模式后显示「Koishi 地址:」一行。

该输入框在回车或失焦时写回，不在输入过程中实时保存，原因是地址变更会重建连接。

未填写协议前缀时会自动补 `ws://`；已包含 `ws://` 或 `wss://` 时保持原样。

地址为空时连接启动失败，不会回退为 Server 模式；失败原因显示在 WebSocket 面板的错误行，内容为「未配置 Koishi 地址」。

## 消息筛选

「消息筛选:」决定群聊消息在什么条件下被当作猜测文本处理：

| 方式           | 调用 AI 的时机                  |
| -------------- | ------------------------------- |
| 仅严格格式匹配 | 只接受标准格式，不调用 AI       |
| 仅 AI 智能匹配 | 每条消息均交由 AI 判断          |
| 先严格再 AI    | 先按格式匹配，未命中时再调用 AI |

默认值为「仅严格格式匹配」。后两种方式需要先在 [AI 模型](ai-models.md) 中配置可用模型，否则 AI 环节失败，消息可能进入丢包列表。

此处设置只影响群聊消息的取用方式，不影响手动输入的判定流程。AI 参与判定的方式与失败处理见 [群聊托管猜测](../guessing/auto-host.md)。

## 安装 Koishi 插件

1. 点击「一键安装 Koishi 插件」。
2. 选择 Koishi 应用根目录（包含 `koishi.yml` 的目录），或其下的 `external` 目录。
3. 程序将插件复制到 `external/adapter-autocmex/`，并弹出安装完成说明。
4. 安装完成后页面底部显示「插件状态: 已安装到 ……」，重启程序后仍然有效。

选择错误的目录会在安装时提示，不会写入其他位置。安装完成的提示给出 Koishi 控制台中的启用路径：插件配置 → 右键 → 添加插件，搜索 `adapter-autocmex`，或查看「适配器」分类。

插件只负责转发消息，猜测判定在 AutoCMEX 内完成，因此 Koishi 侧没有与猜测相关的参数。

> **注意**：若提示未检测到工作区链接，需先在 Koishi 应用目录执行一次 `yarn install`（或 `npm install`），控制台才能加载插件。若提示存在旧版目录 `auto-cmex`，应将其移走：它与本插件声明同一个包名，保留会加载到旧文件。

## 搭建完整链路

Koishi v4 安装并启动后，在控制台启用本插件；再配置一个 OneBot 适配器（例如 NapCat），将 QQ 群消息转发到 Koishi；最后让 AutoCMEX 与 Koishi 使用同一地址与端口。任一环节缺失，群消息都无法进入程序。

## 连接排查

排查连接问题时，以 [WebSocket 状态面板](../run/websocket.md) 显示为准：它反映正在运行的实例，而设置页只记录已保存的配置，两者在连接重建完成前可能不一致。端口占用、地址错误与 Koishi 未启动均表现为连接不上，区别体现在错误行与日志中，必要时查看 [日志](../run/logging.md)。
