# 术语与活动流程

一场 CMEX 活动分为创作、整合、发布、猜测与结束五个阶段，工具参与其中的整合、发布、猜测与结束。各阶段与板块的对应关系、常用术语以及数据流向如下。

## 活动阶段

| 阶段 | 内容                                              | 对应板块                   |
| ---- | ------------------------------------------------- | -------------------------- |
| 创作 | 创作者按活动规则制作作品，提交工程包              | 不涉及，本工具只服务组织者 |
| 整合 | 收齐作品包，合并为一个工程并生成对应表            | 整合                       |
| 发布 | 将 GIF 集、统计表与活动规则发送到活动群，活动开始 | 信息                       |
| 猜测 | 群成员猜测每张符卡的创作者，程序判定并回复        | 猜测                       |
| 结束 | 公布最终统计                                      | 信息                       |

创作阶段不涉及本工具，创作者提交工程包无需安装程序。工具的作用范围从整合阶段开始，到活动结束发布统计表为止；整合板块的使用见 [整合板块概览](../merge/overview.md)。

## 术语

| 词         | 含义                                                                                                        |
| ---------- | ----------------------------------------------------------------------------------------------------------- |
| 项目、工程 | LuaSTG 的工程文件（`.lstgproj`、`.lstges`），对应一名创作者的一份作品                                       |
| 作品包     | 创作者提交的 `.zip`，包含工程与资源，是整合的输入                                                           |
| 符卡       | Boss 的一招，是猜测与统计的最小单位；没有正式卡名的非符在对应表中写作「（非符）」                           |
| Boss       | 一组符卡的归属；程序按 Boss 分别编号，猜测与统计均以当前 Boss 为准                                          |
| 创作者     | 符卡的作者，即需要猜测的对象                                                                                |
| 组织者     | 使用本工具组织活动的人                                                                                      |
| 对应表     | 符卡到创作者的映射，由整合产出，供猜测与信息板块使用                                                        |
| 别名表     | 创作者主名与其他称呼的对照，用于把群成员的叫法转换为主名                                                    |
| GIF 集     | 一份 `manifest.json` 加逐张 `序号.gif`，供信息板块发布；可由 [符卡 GIF 录制](../recording/overview.md) 生成 |
| 丢包       | 群聊猜测处理失败时留下的记录，可以重试                                                                      |
| 活动规则   | 发布到活动群的一段纯文本规则                                                                                |

「已猜出」指群内已被猜中的符卡，与「揭晓」不同：对应表中创作者栏为空的符卡显示为「（未揭晓）」，猜出后该栏才可能有值。

工程与作品包的区别在于：工程指 `.lstgproj` 或 `.lstges` 文件本身；作品包指创作者提交的 `.zip`，其中可以包含多份工程，导入时只读取其中一份，因此约定一包一份工程。

## 角色

组织者负责全部操作：整合工程、维护对应表与别名表、建立群聊连接、判定猜测、发布信息。创作者只需提交作品包，群成员只需在群内发送猜测，均无需使用本程序。程序内的流程面向组织者。

## 数据流向

1. 创作者的作品包进入整合板块，解析符卡并合并工程，导出三列对应表 CSV。
2. 对应表与别名表导入猜测板块，作为判定依据。
3. 群聊消息与手动输入经过同一套处理，判定结果写回对应表。
4. 信息板块（[信息板块概览](../info/overview.md)）读取判定结果，生成两张统计表，与 GIF 集和活动规则一起发布到活动群。

群聊链路的托管、筛选与丢包见 [猜测板块概览](../guessing/overview.md)。

## 上下游关系

> **注意**：对应表既是整合的输出，也是猜测的输入，并且在猜测板块可以修改。修改后，整合侧已导出的 CSV 不会同步更新，两侧数据可能不一致。

Boss 是猜测与信息的共同口径。切换 Boss 后，猜测的符卡编号与信息板块的两张统计表同时改变。

信息板块的两张统计表不单独存储数据，其内容来自猜测板块的判定结果。
