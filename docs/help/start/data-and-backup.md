# 数据存放与备份

AutoCMEX 的数据保存在本机的用户数据目录中，不涉及云端或同步。重装系统、更换电脑或清理磁盘前，需要确认该目录的位置与备份方式。

## 数据目录

数据保存在 Godot 的用户数据目录，Windows 下的路径为 `%APPDATA%\Godot\app_userdata\AutoCMEX\data\`。将路径粘贴到资源管理器地址栏后可以打开，系统会展开 `%APPDATA%`。

该目录与程序安装目录相互独立：升级、重装或删除程序不会修改它，配置因此可以保留。目录在首次启动时自动创建，并按 Windows 账号区分，同一账号下只有一份。

## 目录内容

![用户数据目录内容](images/start-data-and-backup-1.png)

上图为用户数据目录中的文件与子目录。

| 文件或目录              | 内容                                                                 |
| ----------------------- | -------------------------------------------------------------------- |
| `app_settings.json`     | AI 模型、请求超时、群聊端口与模式、Koishi 地址、消息筛选、目标群列表 |
| `spellcard_table.json`  | 猜测板块的对应表                                                     |
| `alias_table.json`      | 创作者别名表                                                         |
| `merge_config.json`     | 整合的模板路径、合并模式与导出选项                                   |
| `creator_packages.json` | 已导入的创作者包列表                                                 |
| `info_config.json`      | GIF 集注册表、当前集、活动规则                                       |
| `recording_config.json` | 录制参数与上次输出目录                                               |
| `key.bin`               | 加密 API 密钥所用的密钥文件                                          |
| `gif_sets` 目录         | 从压缩包导入的 GIF 集解压位置                                        |

这些文件为明文 JSON，可以直接查看。配置修改应通过界面完成，手工编辑可能导致文件无法解析。

## 不在此目录的内容

- 日志：默认位于 `%TEMP%\AutoCMEX\logs`，属于系统临时目录，可能被清理工具删除。需要保留排查依据时应及时复制；查看方法见 [日志](../run/logging.md)。备份数据目录不包含日志。
- 录制产物：保存在录制时选择的输出目录，不随数据目录迁移；输出目录在 [录制设置](../recording/settings.md) 中配置。
- 从文件夹导入的 GIF 集：只记录原文件夹位置，不复制图片。原文件夹被移动或删除后，发布前的预检会报错。相关规则见 [符卡 GIF 集](../info/gif-set.md)。

## 备份与迁移

1. 退出 AutoCMEX，等待自动保存完成。
2. 将整个 `AutoCMEX` 用户数据目录复制到其他位置，`data` 中的 `key.bin` 需一并复制。
3. 更换电脑时，将目录放回同一位置后启动程序。

整个目录一起复制即可，按文件挑选可能遗漏 `key.bin` 与 `gif_sets`。迁移后应检查整合板块中的模板路径与 Sharp 目录：这两项保存为绝对路径，更换电脑后需要重新填写。

> **注意**：仅复制 `app_settings.json` 而不包含 `key.bin` 时，此前保存的 API 密钥无法解密，需要重新填写。

## 重置与安全

从空白状态开始的方式为：退出程序并完成备份，删除或重命名整个用户数据目录，程序下次启动时会重新创建。删除前应确认程序已退出，否则自动保存可能再次写入文件。该操作会清除配置、对应表、别名表与 GIF 集注册，且无法恢复。

安全方面有三点：`key.bin` 与加密后的密钥位于同一目录，获取整个目录即可解出 API 密钥；数据目录与其中的 JSON 文件不应发送给他人，需要协助排查时只提供必要部分；日志会记录发送者与猜测原文，对外分享前应检查内容，并遮蔽截图路径中的用户名与群号。数据目录是本地配置目录，不具备加密保护。
