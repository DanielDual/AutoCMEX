# AutoCMEX — 项目概述

## 项目简介

**AutoCMEX** 是基于 Godot 引擎的桌面 GUI 应用，用于自动化 **CMEX 活动** 的开展过程。

## CMEX 活动介绍

CMEX 是以"猜测创作者"为核心的弹幕创作社区活动，流程如下：

1. **创作阶段**：多位创作者围绕同一角色制作弹幕（符卡），提交给组织者。
2. **整合阶段**：组织者将所有符卡整合为完整作品，不公布各符卡对应的创作者。
3. **发布阶段**：组织者发布完整作品及猜测所需信息。
4. **猜测阶段**：参与者对各符卡的创作者进行猜测，组织者回应。
5. **结束阶段**：所有符卡的创作者均被猜出时，活动结束。

## 术语定义

| 术语 | 英文 | 定义 |
|------|------|------|
| 项目 | Project | AutoCMEX 应用程序本身。 |
| 符卡 | Spell Card | 弹幕的载体之一，创作者提交的基本单元。 |
| Boss | Boss | 符卡与其他游戏内容的载体，只有 Boss 能持有符卡。 |
| 作品 | Work | 包含游戏内容、可由弹幕引擎运行的完整产物。 |
| 创作者 | Creator | 制作作品/符卡的人。 |
| 组织者 | Organizer | 组织 CMEX 活动的人，负责整合、发布、回应猜测。 |

## 功能板块

| 板块 | 说明 | 开发状态 |
|------|------|----------|
| 整合 | 整合多个创作者提交的作品为一个整体项目。 | 暂不开发 |
| 猜测 | 处理对某张符卡为哪位创作者的猜测。 | 待开发 |
| 信息 | 显示作品信息，方便组织者发布。 | 暂不开发 |
| 设置 | 显示和修改各板块的配置。 | 待开发 |
| 帮助 | 提供使用帮助和说明。 | 待开发 |

## 技术栈

- **GUI 框架**：Godot 4.x + .NET 8
- **语言**：C#
- **UI 方案**：Godot 原生 Control 节点
- **外部集成**：AI 模型 API（OpenAI / Anthropic 格式）、Koishi v4 群聊机器人框架
- **进程通信**：WebSocket（AutoCMEX 为服务端，JSON 消息）
- **本地存储**：JSON 文件，AES 加密敏感信息
