# AutoCMEX — UI 设计规范

## 全局布局

### 主窗口布局

└──────────────────────────────────────────┘

### 窗口尺寸与缩放

- 启动尺寸：屏幕逻辑分辨率的 75%，按 project 窗口宽高比（16:9，1280×720）约束后居中；本机 1080p 下为 1440×810。
- 启动尺寸记忆：首次启动仍是上述 75% 居中；用户调整过窗口后，关闭时记下尺寸、位置与最大化状态，下次启动还原（关窗时是最大化就以最大化打开）。记忆尺寸小于最小尺寸（屏幕 25%）时按最小尺寸；记录的位置已不在任何屏幕可见区内（如外接屏拔掉）时回到主屏居中。恢复在 `Main.LookGood` 之后执行，因此不会被 75% 推荐值覆盖；从未调整过则不写记忆，行为与旧版一致。
- 可自由缩放、可最大化：没有最大尺寸限制（旧实现由 `Chickensoft.GameTools` 的窗口化推荐值把上限压在屏幕 75%，现在主窗口初始化时会解除该上限）。
- 最小尺寸：由 `GameTools` 设为屏幕逻辑分辨率的 25%（按 16:9 约束，本机 480×270）。Godot 只在 `Window.WrapControls` 开启时才用「内容最小尺寸」抬高窗口下限，主窗口未开启，因此缩到极小时界面可能被裁切（既有行为，不属于本次解除最大尺寸的改动）。
- 内容缩放保持 `UIFixed`（`GameTools` 固定 UI 缩放）：窗口变大只是可视区域变大，控件与字号的物理尺寸不变；布局由容器自适应（左栏 200 UI 定宽，右栏铺满）。
- 为什么只改最大尺寸：`GameTools` 的 75% 是「窗口化游戏窗口的推荐尺寸」，不是显示缩放正确性的要求；真实 DPI / 原生分辨率校正仍由 `GameTools`（`Chickensoft.Platform`）负责。
- 替代方案与取舍：给 `LookGood` 传 `maxWindowedSize: 1.0` 会把初始窗口也变成满屏；`UIProportional` 会让 UI 随窗口整体缩放，不符合桌面工具；游戏式全屏（`isFullscreen`）不属于本需求。

### 右栏布局

右栏展示当前选中功能板块的内容。所有板块场景在启动时全部预加载，切换时通过显隐控制，各板块维护独立的 `.tscn` 文件。

### 文件选择窗口尺寸

选择文件与选择目录统一用 Godot 内置 `FileDialog`（不启用系统原生对话框），尺寸由 `src/ui/FileDialogSizing.cs` 统一决定：

- 首次唤出：按主窗口**视口尺寸**（内容缩放后的 UI 坐标，不是窗口像素）的 80% 打开，随主窗口尺寸变化重算；不另设上下限，尺寸下限由引擎按对话框内容最小尺寸（随主题缩放变化）自行抬升。
- 尺寸记忆：所有文件选择窗口**共用一份「上次尺寸」**——任一个被拖动并关闭后，之后所有窗口都用它；从未被拖过时按视口 80% 打开。只记录用户真正拖过的尺寸：仅关闭、没拖动不写记忆（引擎把窗口抬到内容最小尺寸也不算拖动），所以主窗口尺寸变化时仍按视口重算 80%。记忆尺寸在显示时收敛到当前视口以内（主窗口缩小后不会留下超出窗口的弹窗），收敛结果不写回记忆（窗口恢复后弹窗仍回到用户当初的尺寸）。跨重启记忆：记录随其它布局数据一起落盘，重启后仍沿用上次拖出的尺寸；没拖过的窗口在重启后依旧按视口八成打开。
- 为什么：引擎给 `FileDialog` 的初始尺寸只有 640×360，无参 `PopupCentered()` 就按它弹；主题缩放 2.0 下内容最小尺寸已是 836×355，文件列表只剩三四行。写死 760×520 的调用点也不随主窗口与缩放变化。
- 为什么按「视口」而不是「窗口像素」：主窗口启动时由 `Main.LookGood` 设置内容缩放（4K 设计在 1080p 上 `content_scale_factor` 为 0.5），此时窗口 1440×810 像素对应视口 2880×1620 UI 坐标；嵌入子窗口的尺寸与 `PopupCentered` 都用 UI 坐标，拿窗口像素当父尺寸会让弹窗只有预期的 0.5 倍大。
- 为什么弹出后还要补设尺寸：Godot 在 popup 嵌入子窗口时会把尺寸钳到「屏幕可用区域」的像素值（不按内容缩放换算），内容缩放 0.5 时会把弹窗钳到 1920×1020 UI 坐标、在屏幕上只有 960×510 像素；因此 popup 之后要再设一次目标尺寸（位置已由 popup 按同一目标居中）。
- 替代方案与取舍：只在少数调用点写死更大像素值——仍有调用点无尺寸且不自适应；全部改用 `PopupCenteredRatio`——每次唤出强制按比例重置，用户上次拖拽丢失；启用系统原生对话框——与既有「不用原生对话框」的决策冲突，且改变弹窗形态与测试口径。

## 各板块 UI 布局

### 整合板块

左右两栏：左栏为创作者包与三类清单，右栏为模板配置、对应表与导出：

| 区域         | 位置 | 内容                                                                                                                  |
| ------------ | ---- | --------------------------------------------------------------------------------------------------------------------- |
| 创作者包信息 | 左上 | 已导入包列表（创作者名 + 包名）、「导入创作者包」、「删除所选包」                                                     |
| 清单         | 左下 | 符卡清单（符卡/非符）、资源清单（贴图/音频等引用）、对象清单（敌机/道具等定义）                                       |
| 工程模板配置 | 右上 | 模板 `.lstgproj` 路径、LuaSTG Editor Sharp Cli.exe 路径、`LuaSTGPlusLib.dll` 路径、「导入并检测注入点」与注入点状态行 |
| 对应表       | 右中 | 符卡→创作者映射列表，上移 / 下移 /「按模式重排」（随机、交替（非符/符卡）、按创作者分组）                             |
| 导出功能     | 右下 | 合并模式（提取式（按类型重放）/ 按顶层文件夹整搬）、选项、输出目录、「导出完整包」与「导出对应表」                    |

- 选项：导出包含 `.lstges` 工程文件、混淆 Lua 脚本（实验性）、冲突自动改名（实验性）、前置对话/移动的符卡强制按 Perform Action 整合、按创作者分组（每人专属文件夹）。
- 自动改名（实验性）只覆盖「多个创作者包内同名资源文件」的自动改名；模板资源同名与对象/定义名冲突不自动改名。
- 「按创作者分组」只在提取式合并下生效；按顶层文件夹整搬模式下置灰，悬停说明原因。
- 「混淆 Lua 脚本（实验性）」只作用于 mod 包内的 `.lua` 脚本；mod 包内是否带工程文件只由「导出包含 `.lstges` 工程文件」决定，混淆开关不参与。
- 混淆失败时在冲突/日志列表给出失败脚本与原因，且不交付半混淆包（Sharp 原始 zip 改名保留为 `.zip.unobfuscated`）。
- 冲突与打包结果统一显示在冲突/日志列表；「导出对应表」单独导出三列对应表 CSV。
- 栏间分割条：左右两栏之间、左栏内部与右栏内部三处都可拖拽；位置（含折叠状态）会被记住，下次启动还原，从未拖动过则用场景默认值。

猜测板块左栏为对应表与别名表（可拖拽分割），右栏为猜测输入与回应；Boss 下拉位于左上「符卡—创作者对应表」的按钮行（默认选中第一个 Boss）。布局示意：

│   （Boss 下拉在左上「符卡—创作者对应表」的按钮行）│
├──────────────────────────────────────────┤
│  ┌─────────────────┐ ┌────────────────┐  │
│  │  符卡—创作者    │ │                │  │
│  │  对应表         │ │  猜测文本      │  │
│  │  (Tree 控件)    │ │  输入框        │  │
│  │                 │ │                │  │
│  │  [按钮区]       │ │  [模糊化处理]  │  │
│  ├─────────────────┤ ├────────────────┤  │
│  │  创作者别名表   │ │  回应显示栏    │  │
│  │  (树状结构)     │ │                │  │
│  │                 │ │                │  │
│  │  [按钮区]       │ │                │  │
│  └─────────────────┘ └────────────────┘  │
└──────────────────────────────────────────┘

| 区域      | 位置       | 内容                                                                                                 |
| --------- | ---------- | ---------------------------------------------------------------------------------------------------- |
| Boss 选择 | 左上按钮行 | 下拉框，切换当前被猜测的 Boss（位于左上对应表 Tree 下方的按钮行，切换后刷新该表）                    |
| 左上      | 左侧上方   | 符卡—创作者对应表（Tree 控件，仅显示当前 Boss）                                                      |
| 左下      | 左侧下方   | 创作者别名表                                                                                         |
| 右        | 右侧       | 上方猜测输入框 + 「处理」/「模糊化处理」按钮，中部回应显示栏，底部丢包列表（重试全部/清空/删除选中） |

- 左上和左下之间为可拖拽分割条（VSplitContainer）；左侧两栏与右侧猜测区之间同样可拖拽（HSplitContainer）。两处分割条的位置（含折叠状态）会被记住，下次启动还原，从未拖动过则用场景默认值。
- 功能按钮（导入、导出、添加、删除）放置在对应栏目旁。
- 工程文件读取由「整合」板块承担（先在整合板块导出对应表再导入）；本栏只有导入对应表/导出等按钮，不预留禁用按钮。
- 未配置 AI 模型时，模糊化处理按钮禁用，hover 提示"请先配置 AI 模型"。

```

│ ┌────────────┬────────────┬────────────┬────────────┐      │
│ │ 符卡 GIF 集 │符卡猜测情况│创作者剩余未 │  活动规则   │  →   │
│ │ [集▾][导入] │    表      │被猜测符卡数│            │      │
│ │            │            │    表      │            │      │
│ │ ┌────────┐ │ ┌────────┐ │ ┌────────┐ │ ┌────────┐ │      │
│ │ │1.符卡名│ │ │表格预览│ │ │表格预览│ │ │文本编辑│ │      │
│ │ │ (动图) │ │ │        │ │ │        │ │ │        │ │      │
│ │ └────────┘ │ └────────┘ │ └────────┘ │ └────────┘ │      │
│ │  [发布]    │  [发布]    │  [发布]    │  [发布]    │      │
│ └────────────┴────────────┴────────────┴────────────┘      │
└────────────────────────────────────────────────────────────┘
```

| 区域         | 位置     | 内容                                                                              |
| ------------ | -------- | --------------------------------------------------------------------------------- |
| 上栏         | 上方     | ScrollContainer 横向滚动 + 内层 HBoxContainer 装四栏（Godot 无 HScrollContainer） |
| GIF 集栏     | 上栏第一 | 集切换下拉、导入文件夹/导入压缩包、录制、卡片列表、发布                           |
| 猜测表栏     | 上栏第二 | 表格预览（与发布图同源）+ 发布                                                    |
| 创作者剩余栏 | 上栏第三 | 表格预览 + 发布                                                                   |
| 活动规则栏   | 上栏第四 | 纯文本编辑 + 发布                                                                 |
| 顶部操作行   | 顶部     | 一键转发 + 猜测表变化自动推送勾选项（目标群在设置页维护，本页不勾选）             |

- GIF 集卡片为「`序号. 符卡名`」标题 + 下方动图；列表懒加载，只播放与视口有交集的卡片（有一点可见即播放）。
- 录制按钮点击后依次为前置检查（引擎目录 / 插件可录制性 / 沙箱根，不通过则只说明原因且不弹任何选择框）→ 手选工程包 zip → 手选输出目录 → 起录；运行期间弹出进度对话框（阶段 + 已完成/失败/总数 + 各 worker 正在录的卡 + 取消），录完自动把输出目录导入为本栏的集并选中。hover 提示由代码在运行时设置（场景里仍是占位文案）。
- 栏内无可发布内容（集内 0 张 / 当前 Boss 无符卡 / 活动规则为空）或该栏正在发布时，其「发布」按钮禁用。
- 设置页未启用任何目标群或正在发布时，「一键转发」禁用。
- 「猜测表变化自动推送」默认未勾选，勾选状态随配置持久化；勾选后符卡猜测情况表内容变化即自动推送（防抖合并；只有表内容真的变了才推，无关数据变化不重发）。任一入口开始发布这张表（「一键转发」或本栏发布）会撤销已排定的自动推送（避免同一张表发两遍），发布期间新到的表变化则在发布收尾补发（不丢一轮里的最后一次变化）。目标群复用设置页的「启用」项，故未启用任何群时只记一条日志、不弹「未选择目标群」打断猜测；成功静默、失败弹结果对话框（失败基本意味着断连）且不自动重试。自动推送进行中「一键转发」禁用。
- 两张表的发布与自动推送都直接发图（图片消息），只有 GIF 集与活动规则走合并转发。
- 目标群在设置板块「信息」类别维护（群 ID + 展示名 + 启用开关），信息页不再提供勾选入口；「刷新群列表」也在设置页：向 Koishi 查询群列表并并入本地（新并入的群默认不启用），与 Koishi 无连接时弹窗提示刷新失败。
- 发布结果通过对话框呈现（逐项成功/失败与原因、失败即停时列出未发送项）；存在失败项时对话框提供「只重试失败项」按钮。
- 两张表的预览支持右键「复制」与按住拖拽导出（Windows）：拖拽跟随表格缩略图拖影，可放置/不可放置的光标由系统绘制；表内无数据或图片未就绪时菜单项禁用、拖动不启动。

#### 群聊类别页（WebSocket 与 Koishi）

「群聊」类别页自上而下是：WebSocket 端口 → 模式（Server / Client）→ Koishi 地址（仅 Client 模式显示）→ 消息过滤模式 → 「一键安装 Koishi 插件」 → 插件状态行。

| 元素        | 形态                           | 交互与状态                                                                                      |
| ----------- | ------------------------------ | ----------------------------------------------------------------------------------------------- |
| 端口        | 数字输入（1–65535）            | 停止改动约 300ms 后写回设置并触发自动保存，避免连续修改反复重连                                 |
| 模式        | 二选一下拉                     | Server = 本机监听端口；Client = 主动连接 Koishi 地址                                            |
| Koishi 地址 | 单行输入（仅 Client 模式显示） | **回车提交或失焦时写回**（去首尾空白）；写入后由设置绑定链路重建连接；地址为空不会回落成 Server |
| 插件状态行  | 自动换行文本                   | 「插件状态: 未安装…」或「插件状态: 已安装到 `<路径>`」，路径取自设置，重启后仍可见              |

页面每次显示时重新从设置同步一次；同步期间控件回发的变化会被忽略，避免只是翻到这一页就白白自动保存一次。

#### 信息类别页的录制设置

「信息」类别页自上而下是：说明 → 目标群列表 → （「刷新群列表」「添加目标群」与状态行同一行）→ **符卡 GIF 录制设置**（整组常显，不再有折叠开关）。整页再套一层纵向滚动，窗口放不下时往下翻即可看全录制设置——这是有意保留的双滚动结构：群列表行数随活动规模浮动，固定 600px 高度单独滚动可稳定占位；录制设置整组较长，交给页面滚动承接，不再靠「点开才出现」。分组布局：

```
┌ 符卡 GIF 录制设置 ───────────────────────────────┐
│ 引擎目录（LuaSTG 根目录，需含 game/ 与 launch）    │
│ [<LuaSTG>           ] [选择目录…] [从 Sharp 推断]│
│ 引擎目录可用，可执行文件：LuaSTGSub.exe            │
│ 并行录制的引擎实例数 [ 4] 实际 worker = min(…)，…  │
│ ──────────────────────────────────────────────── │
│ 沙箱根目录（每轮为每个 worker 建一份引擎副本…）     │
│ [                      ] [选择目录…] [恢复默认]    │
│ 沙箱根：… / 单 worker 约 1.2 GB × 并行度 4 = …    │
│ ──────────────────────────────────────────────── │
│ 录制插件（安装与启用只在你点击按钮后写入引擎目录）  │
│ autocmex：未安装（应用自带，可一键安装）            │
│ danmaku_recorder：未安装（第三方插件…）            │
│ [安装并启用 autocmex] [启用弹幕录制器] [重新检查]  │
│ ──────────────────────────────────────────────── │
│ 高级参数                                          │
│ 帧数上限 [350] 首次间隔 [3] 换挡后间隔 [5] 放缩比 [50]│
│ 间隔 3 ≈ 20 fps、5 ≈ 12 fps；长卡在帧数上限处截断… │
│ 上次输出目录：… / 已更新为 350。                   │
└──────────────────────────────────────────────────┘
```

| 元素         | 形态                | 交互与状态                                                                                                           |
| ------------ | ------------------- | -------------------------------------------------------------------------------------------------------------------- |
| 分组标题     | 普通文本标签        | 仅作分组分隔，不参与交互；切到本页时刷新一次状态                                                                     |
| 目录输入     | 单行输入 + 两个按钮 | 输入在提交/失焦时写回；非法目录保留原值并在状态行说明原因                                                            |
| 状态行       | 自动换行文本        | 可用为绿、需处理为橙；文案即工具提示，不额外弹窗                                                                     |
| 数值框       | 步进 1 的数值框     | 越界输入收敛到区间；并行度 1~32、帧数上限 1~1000、间隔 1~60、放缩比 10~100（步进 5，单位 %）                         |
| 部署按钮     | 依赖状态启停        | 清单损坏或引擎目录未就绪时禁用（清单**缺失**不禁用，安装会把清单建出来）；自家插件已安装时仍可「重装」（升级后刷新） |
| 操作结果提示 | 组内最后一行        | 只在有内容时占位，显示最近一次操作的结果或被拒原因                                                                   |

目录选择用 Godot 内置 `FileDialog`（OpenDir，`UseNativeDialog = false`，未启用系统原生对话框）。面板不做实时校验风暴：状态行在切到本页、切换配置、每次操作后重算。

双滚动的滚轮交接：Godot 4.7 的 ScrollContainer 只在自身滚动值真的变化时才消费滚轮，到边界后事件会自然冒泡给父级容器——「列表到底继续滚页面」由引擎默认提供，本页不写额外代码。效果：指针在目标群列表上时先滚列表；列表到顶/底后，同一档滚轮继续交给页面滚动；列表内容装得下时滚轮直接滚页面。一档步长 = 可见页高 / 8 × 滚轮倍率。

#### 通用类别页（主题）

「通用」类别页只有一个分组，自上而下是：说明行 →「界面主题:」下拉 → 状态行（初始隐藏）。

| 元素     | 形态                       | 交互与状态                                                                                                             |
| -------- | -------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 说明行   | 自动换行文本               | 常量文案，说明选择后立即生效并自动保存、默认主题保持原样                                                               |
| 主题下拉 | 单选下拉，占满整行剩余宽度 | 5 项，默认（Godot 原生）在首位，其后是暗夜（默认）、浅色（默认）、靛蓝夜色、高对比；选中即全局生效并自动保存，无需重启 |
| 状态行   | 自动换行文本，初始隐藏     | 仅当设置里的主题 id 不在清单内（旧配置或手工改坏）时出现，说明已回退到默认主题；改选到清单内的主题后隐藏               |

下拉始终由设置里 `ThemeId` 的绑定保持同步（不依赖页面显示事件）：外部改动设置会回填到下拉，回填本身不会反写设置，避免只是翻到这一页就白保存一次；设置里的 id 不在清单内时回填为「默认」并显示状态行。

### WebSocket 状态面板

右栏的 WebSocket 页面显示**当前实例**的真实状态（一律取自 `IWebSocketServer` 的 `Mode`/`Port`/`Url`/`LastError`，不取自设置——设置改动后实例重建前两者可能短暂不一致）：

| 位置       | 内容                                                                                                                                                                             |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 模式行     | `模式: Server（等待连接）` / `模式: Client（主动连接）`                                                                                                                          |
| 状态行     | 前缀 `状态: ` 是场景里的独立标题，值只有状态本身：Server `运行中` / `已停止`，Client `已连接` / `未连接（重连中）` / `未连接`，并按运行与否着绿 / 红；按钮启停按 `IsActive` 判定 |
| 端口行     | Server 模式为 `端口: <实际监听端口>`；Client 模式为 `地址: ws://…`（含 Token 的完整对端地址）                                                                                    |
| 连接数行   | 仅 Server 模式显示 `连接数: N`；Client 只有一条链路、与状态行重复，整行隐藏                                                                                                      |
| 事件行     | 最近一次连接/断开等事件                                                                                                                                                          |
| 错误行     | 红色自动换行文本，显示最近一次启动/运行失败的原因（如「未配置 Koishi 地址」）；无错时隐藏                                                                                        |
| 开关按钮   | Server：启动 / 停止；Client：连接 / 断开                                                                                                                                         |
| 客户端列表 | 标题随模式变（`已连接客户端:` / `连接的对端:`），随连接/断开事件立即刷新、内容不变时不重建，另有每秒兜底                                                                         |

状态行、事件行、错误行与连接数由实例事件（状态变化、客户端连接与断开）驱动立即刷新；1Hz 定时器只作兜底，防止事件漏发或状态经非事件路径改变。

## 设计原则

1. **左窄右宽**：左栏仅用于导航，右栏为主要工作区。
2. **板块隔离**：切换板块时右栏内容完全替换，各板块 UI 独立。
3. **一致性**：同类操作的按钮风格保持一致。
4. **响应式**：窗口缩放时右栏自适应，左栏保持固定宽度。
5. **状态反馈**：不可用功能以禁用态展示并给出 hover 提示，导入失败弹窗告知具体错误。
